# krizaka-tauri-kit — agent contract

> Governance of **`krizaka/krizaka-tauri-kit`**. Decision: [krizaka/.github ADR-005](https://github.com/krizaka/.github/blob/main/docs/adr/ADR-005-tauri-app-kit.md).

## What belongs here

- The desktop code every Krizaka Mac app needs the same way. The **rules** (folder scope, files, the drop gate, the
  navigation guard, deep links, the menu checks, secrets, settings, the update channel) are the root crate: pure Rust, no
  `tauri` dependency, tested on any machine. The **glue** that applies them (commands, events, the Keychain, the native
  menu, `RunEvent::Opened`) is `plugin/` (`tauri-plugin-krizaka`); it decides nothing the root crate does not check.
- Not here: a product's commands, its sidecar, its messages, its brand. Those are the product's, wired from
  `template-tauri-app`. The page side of the plugin is `@krizaka/app-desktop` (krizaka-ui): its `COMMANDS` list and
  `plugin/build.rs` change together.

## Rules

- **A read goes through `ScopeStore::resolve`.** Never a path from the UI used directly.
- No product word, no network, no environment read in these crates: values arrive as parameters (`Builder`).
- Every refusal has a test: `..`, a symlink out of a grant, a never-grantable folder, a look-alike host.
- A change to what may be granted or to the guard's rules is breaking: apps in the wild depend on it.

## Before you open or update a pull request (coding agents)

These are the defects code review found most often on 2026-10-23. Check them yourself before you open or update a pull request:
1. **Checks:** run the repository's full check (lint, typecheck, tests, build) and fix it. Never push a red check.
2. **Concurrency:** any « count then insert » or « check then write » runs in one transaction with a lock, and has a concurrency test.
3. **One gate:** a rule (limit, permission, validation) is enforced in the service, so no route can skip it. Test every route.
4. **Errors:** a cleanup (ROLLBACK, DROP, close) never masks the original error. Rethrow it, or throw an `AggregateError` with the original first.
5. **Validation:** validate the original input, never a truncated or pre-trimmed copy. Server and client reject the same inputs.
6. **Accessibility:**
   - every control has a unique label, and FR/EN pairs say their language;
   - focus rings are never clipped by `overflow`;
   - text never overflows its box at 360 px.
7. **Naming:** environment variables follow `<CONTEXT>_<THING>` (`APP_`, `DATABASE_`, `AUTH_`, `MEDIA_`, `MAIL_`, `PAYMENTS_`, `AI_`…) and are declared once.
8. **Words:** every user-facing string is in the FR and EN messages, and no colour is hard-coded.
9. **Review threads:** answer every one. Fix it test-first, or reply with the reason, then resolve it.
